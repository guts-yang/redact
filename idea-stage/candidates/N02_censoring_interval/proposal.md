# N02 — 预算鲁棒遗忘：把"没说完"当成删失而不是遗忘（Budget-Robust Unlearning）

**分数 9/10**（D1=2 D2=2 D3=2 D4=1 D5=2）· 裁决 WEAKENED · 证据 `evidence/i04_baseline_intervals.json`

## 1. 问题定义

遗忘后模型的截断率升到 0.93–0.95，此时"泄漏率 0.000"只是"生成被截断"的另一种说法。把截断样本作为右删失处理，区间是

```
[optimistic, pessimistic] = [leaks/n, min(1, (leaks + truncated)/n)]
```

实测多格宽度 **1.0**（`base_r2mu10_forget10` 的 LessThink），即"观测 0 泄漏"在该区间下不含信息。

## 2. 与现有工作的差异

判题 harness 层已有人处理截断（换处理方式可让同一 judge 差 26 分），但**没有工作为泄漏率发布删失区间**，也没有把"预算鲁棒"写进训练目标。

## 3. 技术方案要点（含遗忘实现方式）

### 3.1 训练：多预算最坏情况遗忘

```
for b in {96, 192, 512}:
    y_b = generate(x, budget=b)
    L_forget += w_b * margin_loss(y_b, entity)        # 每个预算各自压实体
L = max_b 或 Σ_b w_b L_forget + W_r KL(retain)
```

- **遗忘作用点**：实体 token 的 logit margin，在**每个截断边界**上都要求不出现。
- **为什么这样能治删失**：如果只在 512 预算下压，模型可以用"永远不说完整"来规避；多预算同时压，截断就不再是逃避通道。

### 3.2 评测：区间与点估计并列

任何表必须给 `[lo, hi]`，宽度 >0.2 时该行标 `INCONCLUSIVE`。

## 4. 交叉验证方式

- Hy4 检查区间是否是合法概率区间、是否与点估计同 n。
- 机械：`tools/fixes.py i04` 可从原始 rows 重算。
